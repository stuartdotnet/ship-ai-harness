# Talk material

A 45-minute conference/meetup talk on this repo: *My ship's AI told me it was cooling the reactor*.

The shape is **build it, then break it**: twelve minutes walking the actual code, then the two
failures that came out of running it — the agent inventing actions it has no tools for, and the
agent answering confidently from a world that moved two turns ago.

| File | What it is |
| --- | --- |
| `outline.md` | The full outline — spine, timing map, act-by-act beats, cut lines, and answers to the likely questions |
| `demo-runbook.md` | The two live demos, keystroke by keystroke, with a pre-flight checklist and a recovery cheatsheet |
| `deck.html` | The presentation deck as a browser slide runner. Speaker notes and a talk timer built in |
| `diagram-prompts.md` | Ready-to-paste prompts for generating the deck's diagrams in Copilot/ChatGPT |
| `ship-ai-harness-talk.pptx` | The same 41 slides as PowerPoint, with the notes in the notes pane |
| `ship-ai-harness-talk.pdf` | Flattened backup, for a laptop that will not open either of the above |
| `opening-panel.txt` | Real captured console output, seed 1701, T000 — the source for the fallback slide |

## Presenting from `deck.html`

Open the file in any browser. Nothing to install and no network needed except the web fonts,
which fall back cleanly.

| Key | Does |
| --- | --- |
| `→` `space` | Next slide |
| `←` | Previous |
| `S` | Speaker-notes drawer (the stage shrinks to fit beside it) |
| `T` | Start/stop the talk timer — it reports whether you are ahead of or behind that slide's cue |
| `R` | Reset the timer to zero |
| `O` | Overview grid, click any slide to jump |
| `F` | Full screen |

Every slide carries a cue time. The timer compares elapsed against the current slide's cue, so
"+3 min behind" means exactly that — you are three minutes past where this slide should have
landed.

For a two-screen setup, the notes drawer is on the same screen as the deck by design; mirror the
display and read the drawer, or present from the `.pptx` where the notes pane is separate.

## The code slides

Slides 10–19 are syntax-highlighted listings straight out of `src/`, lightly abridged to fit —
ellipsis comments mark anything cut. Both decks highlight from the same small tokeniser (a regex in
`deck.html`'s first script block, and `tokenize()` in `build-deck.py`), so a listing looks the same
in the browser and in PowerPoint.

If you edit a listing, keep it honest against the file it names. The kicker on each of those slides
is the real path, and somebody in the room will open it.

## Keeping the deck honest

The numbers on the slides come from the repo, so they drift when the repo does. Three to re-check
before you present:

- **`dotnet test`** — the deck says 38 tests (slides 9, 37, 41). Update it if that has moved.
- **Milestone status** — slides 36 and 41 claim what is built. `../milestones.md` is the source of
  truth; re-read it before you present if the repo has moved on.
- **The panel screenshots** are seed 1701 on `derelict-freighter`. Regenerate with
  `SHIPAI_SEED=1701 dotnet run --project src/ShipAI.Console` if the render changes.

And **slide 2 is a placeholder.** It has your name on it and not much else — fill in the day job
before you stand up.

## Rebuilding the .pptx

`deck.html` is hand-maintained. The `.pptx` is generated by `build-deck.py` (python-pptx).
For small changes, edit the PowerPoint directly. For a restructure:

```bash
python3 -m venv .venv && .venv/bin/pip install python-pptx
.venv/bin/python docs/talk/build-deck.py
```

Slide content lives in one call per slide at the bottom of that file; the layout primitives
(`terminal`, `code`, `bullets`, `quote`, `table`, `act_break`, `demo_card`) are at the top.

The two decks are kept slide-for-slide in step, and `outline.md` is the contract between them — if
you restructure one, restructure all three.

To refresh the flattened PDF backup:

```bash
libreoffice --headless --convert-to pdf --outdir docs/talk docs/talk/ship-ai-harness-talk.pptx
```
