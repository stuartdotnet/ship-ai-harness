why a starship

A to-do app cannot fail interestingly

  • State moves underneath the agent — between turns, without it being told
  • Refusals are informative — “insufficient reactor output”, not an exception
  • Consequences are asymmetric — some reversible, one of them kills people
  • It is deterministic — same scenario, same seed, same voyage, every time

Also: nobody has ever been bored by a hull breach.

Be honest about why the domain is silly — it is a deliberate choice, not a gimmick. I needed a domain where the world moves on its own, where refusing tells you something, where the blast radius of different actions is genuinely different, and where I can run the same thing twice and get the same answer. The first bullet is the one that matters most — it is the second failure in this talk, and every business agent has it too. Your ticket got reassigned. Your invoice got paid. The agent does not know. Land the last line, then move.

level-set

A harness is not a chat client

  • A chat client sends messages and hands you back text. You write the loop.
  • A harness is the loop — it keeps calling until the model stops asking for tools
  • Context providers inject state into every turn, before the model sees it
  • Batteries — todo list, modes, compaction, file memory, web search, approval gate

Microsoft.Agents.AI.Harness 1.15.0 · .NET 10 · new, moving, pinned exactly.

For the half of the room who have not built an agent. "The model cannot do anything. It can only ask. Something has to take 'please call ScanSector' and actually call ScanSector, then hand the result back and ask again. That loop is the harness." "You can write that loop yourself in an afternoon. What you get from a harness is the sixty things around it you have not thought about yet — and that is both the pitch and the problem." Flag ahead: "batteries included is a great line until you find out which batteries are already wired in. Twenty minutes from now."

src/ShipAI.Console/Program.cs

One order, one turn, one tick

while (true)
{
    var order = ShipConsole.Prompt(simulation.State);

    if (order is null or "/quit")  break;
    if (order.StartsWith('/'))     { RunSlashCommand(order); continue; }

    simulation.Log.Append(simulation.State.Turn, LogSource.Captain, order);

    if (!await RunAuroraTurnAsync(order)) continue;

    // One tick per completed agent turn. The world moves when the agent acts,
    // not on a wall clock — which is exactly what makes this reproducible.
    var mark = simulation.Log.Count;
    simulation.Tick();

    ShipConsole.Events(simulation.Log.Since(mark));
    ShipConsole.StatusPanel(simulation.State);
}

The tick is the host's business in milestone 1. Milestone 2 moves it into the context provider — advancing the world is an ambient concern of the turn, not of whichever UI is attached.

The REPL. Read an order, run a turn, advance the world, redraw. Point at the comment. "One tick per completed agent turn. Not a timer. The world moves when the agent acts." Then the honest bit: "the tick lives in the console here because in milestone 1 there is nothing else to put it in. That is a smell — advancing the world is not the terminal's job. Milestone 2 moves this line into the context provider, and that is the second half of this talk." Point at Log.Since(mark). "Scenario events get narrated to the captain here. Remember that — it matters in twenty minutes."

await foreach (var update in aurora.RunStreamingAsync(order, session))

src/ShipAI.Agent/Tools/SensorTools.cs

A tool is a method with a good description

[Description("""
    Sweeps the current sector and returns every sensor contact: contact ID,
    designation, bearing in degrees, range in AU, and drive signature. Use the
    returned contact IDs with AnalyseContact. The result is a snapshot stamped
    with the turn it was taken on. Contacts arrive and depart between turns, so
    a sweep from an earlier turn is not evidence about this one.
    """)]
public string ScanSector()
{
    var contacts = simulation.State.Contacts;

    if (contacts.Length == 0)
        return Stamped("Sector sweep complete. No contacts. Background only.");

    // …one line per contact: id, designation, bearing, range, drive signature
}

private string Stamped(string reading) => $"[T{simulation.State.Turn:D3}] {reading}";

src/ShipAI.Simulation/ShipSimulation.cs

The world changes in exactly two places. One:

public CommandResult Apply(ShipCommand command)
{
    var result = command switch
    {
        RoutePower     c => ApplyRoutePower(c),
        SealBulkhead   c => ApplySealBulkhead(c),
        VentAtmosphere c => ApplyVentAtmosphere(c),
        PlotJump       c => ApplyPlotJump(c),
        SetAlert       c => ApplySetAlert(c),
        _ => CommandResult.Refused($"Unrecognised command: {command}.", State),
    };

    State = result.State;
    Log.Append(State.Turn, LogSource.Aurora,
        result.Success ? result.Narrative : $"REFUSED — {result.Narrative}");

    return result;
}

src/ShipAI.Simulation/ShipSimulation.cs

Two: the clock

public ShipState Tick()
{
    _clock.Advance();
    State = State with { Turn = _clock.CurrentTurn };

    foreach (var e in _scenario.Events.Where(e => e.Turn == State.Turn))
    {
        State = ApplyScenarioEvent(e);
        Log.Append(State.Turn, LogSource.Ship, e.Narrative, SeverityOf(e.Kind));
    }

    State = ApplyAtmosphere();
    State = ApplyReactorHeat();
    State = ApplyCasualties();
    State = ApplyAlertEscalation();

    return State;
}

Breaches bleed. Reactors bake. Crew suffocate. Alerts escalate on their own. All of it happens to the agent, none of it is told to the agent.

"And this is the second place the world changes: the clock. Once per completed agent turn." Walk the four Apply calls at the bottom. "Breaches bleed thirty a turn. The reactor bakes if you over-allocate and sheds heat if you run lean. Crew in a vacuum die on the next tick. Alert escalates automatically — standing down is a decision, and the next tick puts it back if the conditions are still true." "A ship that reports GREEN with a compartment venting is worse than no indicator at all, because the captain stops reading it." THE LINE THAT MATTERS, say it slowly: "every one of those things happens TO the agent. None of it is told to the agent. The captain sees it on the panel. AURORA does not." One immutable record is the whole ship

public sealed record ShipState
{
    public required int          Hull     { get; init; }
    public required ReactorState Reactor  { get; init; }
    public required Coordinates  Position { get; init; }
    public required AlertLevel   Alert    { get; init; }
    public required int          Turn     { get; init; }

    public required ImmutableDictionary<ShipSystem, int>     PowerAllocation { get; init; }
    public required ImmutableDictionary<string, ShipSection> Sections        { get; init; }
    public required ImmutableArray<CrewMember>               Crew            { get; init; }
    public required ImmutableArray<Contact>                  Contacts        { get; init; }

    public IEnumerable<CrewMember> CrewIn(string section) =>
        LivingCrew.Where(c => string.Equals(c.Section, section, OrdinalIgnoreCase));
}

ShipSimulation holds the only mutable reference and replaces it wholesale. Everything else — panel, tools, tests — works with snapshots.

Be terse. A bridge is not a place for paragraphs. Two or three sentences is a

the one that will bite you in production

Compaction is off unless you set both limits

MaxContextWindowTokens = 128_000,
MaxOutputTokens        = 16_384,     // set one and not the other:
                                     //   no compaction, no warning, no error

The compaction provider is added to the pipeline only when both are non-null.

You find out on the turn the context window overflows.

Thirty seconds, but make it land — this is the one that costs someone in the room a production incident. "Compaction is what keeps a long conversation inside the context window. the boring part that makes the rest possible

38 tests. No model calls. Under half a second.

  • Same scenario + same seed = same voyage — every time
  • Which makes every panel in this deck reproducible — seed 1701, captured not mocked
  • And makes a ten-run comparison a comparison — not an anecdote

take these home

Five things

  • Constrain verbs, not just nouns. “Don't invent readings” does not stop it inventing actions — and it sounds entirely credible doing so.
  • Tell it what changed; let it ask for the rest. An agent will never ask about something it does not know has happened.
  • Read the defaults as decisions you have not made yet. Three providers were on before I chose anything; two wrote to disk at construction.
  • Gate by consequence, not category. And make the gate say who is standing in the room.
  • Keep the domain free of the framework. It is what makes any of this testable, repeatable, and honest.
The close. All five are transferable — none of this is C#-specific. Walk them briskly. Do not re-explain; they have just seen the evidence for every one. The order is deliberate: the two failures first, because those are the ones they will hit.
